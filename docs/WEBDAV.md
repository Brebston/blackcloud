## WebDAV: хмара як мережевий диск

Адреса: `https://<домен>/dav/` (наприклад, `https://brebston.com/dav/`). Підтримуються RFC 4918 класи 1 і 2 (PROPFIND, PROPPATCH, GET/HEAD з Range, PUT, DELETE, MKCOL, COPY, MOVE, LOCK/UNLOCK) і квоти RFC 4331 (`quota-available-bytes`/`quota-used-bytes`).

### Пароль застосунку
Акаунти мають 2FA, тому WebDAV використовує окремі **паролі застосунків**: Налаштування → WebDAV → «Створити пароль» (потрібен поточний пароль акаунта). Пароль (~170 біт) показується один раз; у БД — лише Argon2-хеш. До 10 паролів на користувача, кожен можна відкликати (діє одразу). Ім'я користувача — логін акаунта. **Основний пароль акаунта для WebDAV не приймається.**

### Підключення
- **macOS (Finder):** ⌘K (Перехід → Підключитися до сервера) → `https://<домен>/dav/` → «Зареєстрований користувач», логін і пароль застосунку. Щоб Finder не створював `.DS_Store` на мережевих дисках: `defaults write com.apple.desktopservices DSDontWriteNetworkStores -bool true`.
- **Windows (Провідник):** «Цей ПК» → «Підключити мережевий диск» → папка `https://<домен>/dav/`, «Використовувати інші облікові дані». Потрібна запущена служба «Веб-клієнт» (WebClient). Windows за замовчуванням не завантажує файли понад ~50 МБ: збільште `FileSizeLimitInBytes` (DWORD) у `HKLM\SYSTEM\CurrentControlSet\Services\WebClient\Parameters` (наприклад, до `4294967295`) і перезапустіть службу (`net stop webclient && net start webclient`). Basic-автентифікація у Windows дозволена лише через HTTPS — це якраз наш випадок.
- **Linux:** GNOME Files — «Інші місця» → `davs://<домен>/dav/`; KDE Dolphin — `webdavs://<домен>/dav/`; davfs2 — `mount -t davfs https://<домен>/dav/ /mnt/cloud` (облікові дані в `/etc/davfs2/secrets`). Також працюють rclone (`type = webdav`, `vendor = other`) і Cyberduck.
- **iOS/iPadOS, Android:** вбудовані файлові менеджери WebDAV не підтримують; використовуйте застосунки з WebDAV через HTTPS (Documents by Readdle, FE File Explorer, Cyberduck; Solid Explorer, CX File Explorer, Material Files).

### Поведінка та обмеження
- Видно лише **власні** файли й папки (не кошик, не незавершені завантаження). «Поділилися зі мною» через WebDAV не показується — лише у вебінтерфейсі.
- **Антивірус:** нові й перезаписані файли перевіряються ClamAV; доки перевірку не завершено, GET повертає 403 з поясненням («Файл ще перевіряється антивірусом…»). Невеликі файли (до `SCAN_INLINE_MAX_KB`, типово 1024 КБ — зокрема службові `._*` і `.DS_Store`, які Finder читає одразу після запису) перевіряються одразу в самому запиті, тож доступні миттєво; більші — у черзі worker-а. Якщо clamd недоступний, файл іде в чергу (правило «доступний лише після перевірки» не змінюється). Заражені файли не віддаються ніколи; копіювати на сервері (COPY) можна лише перевірені файли.
- Завантаження (PUT) іде тим самим шляхом, що й з вебінтерфейсу: шифрування, атомарна квота (немає місця → 507), ліміт `MAX_FILE_SIZE_GB`, ClamAV, мініатюри, аудит (`file.uploaded`, `via=dav`).
- **Перезапис** файлу створює нову версію (історія версій, як в онлайн-редакторі). Порожня «проміжна» версія, яку Finder/Windows створюють перед записом вмісту, в історії не зберігається.
- **DELETE** переносить у кошик (як у вебінтерфейсі), **MOVE з перезаписом** — старе призначення теж іде в кошик.
- **COPY** перешифровує вміст (ключ і AAD прив'язані до id файлу, тож повторно використати шифротекст неможливо); копія знову проходить антивірус. Рекурсивне копіювання папок — до 1000 елементів і `DAV_COPY_MAX_BYTES` (2 ГБ за замовчуванням), більші — 403 з поясненням.
- Службові файли macOS (`._*` AppleDouble, `.DS_Store`) **приймаються як звичайні** (найпростіша й передбачувана поведінка: якщо їх відхиляти, Finder може переривати копіювання з помилкою). Їх видно у вебінтерфейсі; див. команду вище, щоб `.DS_Store` не створювались.
- Блокування (LOCK) живуть у Redis до 1 години (типово 10 хв); мертві властивості PROPPATCH (Finder/Windows) приймаються з відповіддю 200, але не зберігаються.
- PROPFIND з `Depth: infinity` (або без Depth) відхиляється (403 `propfind-finite-depth`).
- Traefik: `--entrypoints.websecure.transport.respondingTimeouts.readTimeout=300s` обмежує час одного запиту — дуже великий PUT на повільному каналі (понад 5 хв) буде перервано. За потреби збільште тайм-аут.

### Безпека
- Лише HTTP Basic з паролем застосунку і лише через HTTPS (`WWW-Authenticate: Basic realm="BlackCloud", charset="UTF-8"`). Сесійні cookie для `/dav/` ігноруються (тож CSRF неможливий); запити, які браузер позначає як міжсайтові (`Sec-Fetch-Site`/`Origin`), відхиляються.
- Невдалі спроби: 5 на логін (20 на IP) → блокування на 15 хв, окремо від входу у вебінтерфейс. Аудит: `dav.auth_failed`, `dav.locked`, `dav.password_first_use`, `dav.password_created`, `dav.password_revoked`. Після успішної перевірки Argon2 результат кешується 5 хв за HMAC(SECRET_KEY, логін+пароль); відкликання пароля діє одразу.
- XML-тіла розбираються без DTD і сутностей (захист від XXE і «billion laughs»), до 64 КБ.
- Шляхи: `.`/`..`, закодовані `/` і `\` (`%2F`, `%5C`), керівні символи — 400. `Destination` — лише той самий хост і префікс `/dav/` (інакше 502). Імена нормалізуються в NFC (macOS надсилає NFD).
- Вміст завжди віддається як `application/octet-stream` + `attachment` + `CSP: sandbox` (як звичайне завантаження з основного домену).

### Ліміти тіла запиту (зміни інфраструктури)
- Для шляхів `/dav/` (і лише для них) `BodyLimitMiddleware` (ASGI) і `MaxBodySizeMiddleware` дозволяють `Transfer-Encoding: chunked` без `Content-Length` (Finder) і тіло до `MAX_FILE_SIZE`; `X-Expected-Entity-Length` понад ліміт → 413 одразу. Для решти шляхів — як і раніше (411 / 20 МБ).
- Django під ASGI спершу складає тіло запиту в тимчасовий файл. `/tmp` у контейнері — tmpfs на 256 МБ, тому новий параметр `FILE_UPLOAD_TEMP_DIR` (типово `<LOCAL_OBJECT_STORE_DIR>/.tmp`, у Docker — `/data/objects/.tmp` на томі `objects_data`) стає `tempfile.tempdir` процесу (створюється під час старту, `apps.dav`). Якщо теку створити не вдалося — лишається `/tmp` (попередження в журналі). Під час великого PUT на томі тимчасово потрібно ще стільки ж місця, скільки важить файл.
- Traefik: маршрут `dav` (`Path(/dav) || PathPrefix(/dav/)`) з `security-headers` + `api-csp` і окремим лімітом частоти `dav-ratelimit` (3000 запитів/хв, burst 1500) — Finder робить ~10 запитів на кожен файл. Буферизації тіла немає.
- З'єднання з PostgreSQL закриваються після кожного запиту (`DB_CONN_MAX_AGE=0` — рекомендація Django для ASGI): з `CONN_MAX_AGE=60` масове копіювання через Finder вичерпувало `max_connections` («remaining connection slots are reserved…», 500).
- WebDAV обслуговує **окремий сервіс `dav`** (той самий образ, `command: dav`, `DAV_WORKERS` процесів, типово 2). Масове копіювання з Finder навантажує лише його, тож вебінтерфейс (вхід, API) лишається доступним. Раніше /dav/ ішов у `backend`: кілька сотень паралельних PUT займали всі його воркери, перевірка стану Traefik не встигала відповісти, і Traefik відповідав «no available server» (503) на всі запити.
- У Traefik для `backend`/`dav` немає `healthCheck`: сервер у кожного один, тож перевірка лише вимикала його при першій повільній відповіді. Стан контролюють Docker healthcheck і моніторинг (Uptime Kuma).
