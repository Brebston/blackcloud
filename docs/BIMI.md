# Логотип біля листів (BIMI)

BIMI (Brand Indicators for Message Identification) — стандарт, за яким поштові сервіси
(Gmail, Yahoo, Apple Mail тощо) показують логотип відправника поруч з його листами.
Це **налаштування DNS і політики пошти, а не функція застосунку**: BlackCloud лише може
роздавати файл логотипу через HTTPS.

> **Фото профілю в BlackCloud ≠ BIMI.** Фото, яке користувач завантажує в «Налаштування →
> Профіль», бачать лише користувачі цього BlackCloud (у чаті, веб-пошті, адмінці). Отримувачі
> в Gmail чи Outlook його не бачать: зовнішні сервіси не мають доступу до наших фото і не
> беруть їх із листа. BIMI показує **один логотип на весь домен**, а не фото окремих людей.

## 1. Передумови: SPF, DKIM, DMARC з примусовою політикою

BIMI працює лише для листів, що проходять **DMARC** із **вирівнюванням** (alignment) за доменом
з поля `From:`, а сама політика DMARC має бути «примусовою».

| Що | Вимога | У BlackCloud |
|---|---|---|
| SPF | `pass` для домену відправника | `TXT example.com` → `v=spf1 mx -all` (див. таблицю DNS у README) |
| DKIM | підпис `d=` того ж домену, що й `From:` | Rspamd підписує листи; запис `mail._domainkey.example.com` — вивід `make dkim` |
| DMARC | `p=quarantine` або `p=reject`, **без** `pct` менше 100 | README радить `v=DMARC1; p=quarantine; rua=mailto:postmaster@example.com` — цього достатньо |

Важливо:

- `p=none` **не підходить** — логотип не показуватиметься.
- `pct` має бути 100 (або взагалі відсутній — за замовчуванням це 100).
- Політика має стосуватися організаційного домену (`_dmarc.example.com`). Якщо задано `sp=none`
  для піддоменів, деякі сервіси вважатимуть політику недостатньою — краще не послаблювати `sp`.
- Перш ніж переходити на `p=reject`, кілька тижнів подивіться звіти `rua`: переконайтеся, що
  всі легітимні листи (зокрема розсилки зі сторонніх сервісів) проходять SPF/DKIM.

Перевірка: надішліть лист на Gmail, відкрийте «Показати оригінал» — там мають бути
`SPF: PASS`, `DKIM: PASS`, `DMARC: PASS`.

## 2. Логотип у форматі SVG Tiny PS

Звичайний SVG не підходить. Потрібен профіль **SVG Tiny Portable/Secure (SVG Tiny PS)**:

- кореневий елемент: `<svg version="1.2" baseProfile="tiny-ps" xmlns="http://www.w3.org/2000/svg" viewBox="0 0 512 512">`;
- обов'язковий елемент `<title>` з назвою організації;
- **квадратне** зображення (співвідношення сторін 1:1), логотип по центру; рекомендовано
  суцільне (непрозоре) тло — сервіси обрізають логотип у коло або квадрат з заокругленнями;
- **заборонено**: скрипти, анімації, зовнішні посилання й зображення (`<image>`, `xlink:href`
  на файли), атрибути `x`/`y` на кореневому `<svg>`, вбудовані растрові картинки;
- розмір файлу — бажано до **32 КБ**.

Як отримати такий файл:

1. Експортуйте логотип у SVG (Illustrator: «SVG Tiny 1.2»; Inkscape: «Звичайний SVG»).
2. Конвертуйте в SVG Tiny PS — вручну (замінити заголовок `<svg>`, додати `<title>`, прибрати
   заборонені елементи) або конвертером: BIMI Group публікує інструкції та посилання на
   інструменти конвертації на [bimigroup.org](https://bimigroup.org/) (розділ про створення
   SVG-логотипа). Існують і сторонні утиліти з назвою на кшталт «svg-tiny-ps converter» —
   перевіряйте результат валідатором, а не довіряйте конвертеру наосліп.
3. Перевірте файл валідатором (див. розділ 6).

## 3. Де розмістити логотип у BlackCloud

Покладіть файл у репозиторій як `frontend/public/bimi/logo.svg` і перезберіть образ фронтенду
(`docker compose build frontend && docker compose up -d frontend`). Після збірки файл
доступний за адресою:

```
https://<DOMAIN>/bimi/logo.svg
```

Перевірте, що сервер віддає саме SVG, а не сторінку застосунку:

```sh
curl -sI https://<DOMAIN>/bimi/logo.svg | grep -i content-type   # очікується image/svg+xml
```

Якщо у відповідь приходить `text/html`, у `frontend/nginx.conf` бракує окремого блоку для
`/bimi/` (інакше SPA-правило `try_files $uri /index.html` віддає головну сторінку замість 404):

```nginx
location /bimi/ {
    add_header Cache-Control "public, max-age=86400";
    try_files $uri =404;
}
```

Логотип може лежати й на будь-якому іншому HTTPS-хості — головне, щоб URL був публічним, з
дійсним сертифікатом і без переспрямувань на сторінки входу.

## 4. DNS-запис BIMI

Запис додається для домену, який стоїть у полі `From:` (у BlackCloud це `MAIL_DOMAIN`):

| Запис | Значення |
|---|---|
| `TXT default._bimi.example.com` | `v=BIMI1; l=https://example.com/bimi/logo.svg; a=;` |

- `l=` — HTTPS-адреса SVG-логотипа;
- `a=` — HTTPS-адреса сертифіката VMC/CMC (`.pem`); якщо сертифіката немає, лишайте `a=;`
  порожнім;
- `default` — селектор за замовчуванням; інші селектори використовують лише за потреби
  (заголовок `BIMI-Selector` у листі), BlackCloud його не додає.

З сертифікатом запис виглядає так:

```
default._bimi.example.com. TXT "v=BIMI1; l=https://example.com/bimi/logo.svg; a=https://example.com/bimi/vmc.pem;"
```

(файл `vmc.pem` можна покласти поруч: `frontend/public/bimi/vmc.pem`).

## 5. Хто що показує і чи потрібен сертифікат

| Сервіс | Сертифікат | Примітки |
|---|---|---|
| **Gmail** | **Потрібен VMC або CMC** | Без сертифіката логотип не показується. З VMC також з'являється синя позначка «перевірено». |
| **Apple Mail** (iCloud, iOS/macOS) | **Потрібен** (VMC; щодо CMC — *уточніть актуальну політику Apple*) | Логотип показується отримувачам на iCloud Mail. |
| **Yahoo / AOL** | Не обов'язковий | Показують BIMI без сертифіката, але лише відправникам із достатнім обсягом і доброю репутацією — для маленького сервера логотип може не з'явитися. |
| **Fastmail** | Не обов'язковий (*за даними на момент написання*) | |
| **Outlook / Microsoft 365** | — | BIMI станом на момент написання не підтримує (*може змінитися*). |

**VMC (Verified Mark Certificate)** — платний сертифікат від уповноваженого центру
сертифікації (наприклад, DigiCert, Sectigo, GlobalSign; перелік змінюється — перевіряйте на
bimigroup.org). Потрібна **зареєстрована торговельна марка** з логотипом у відомстві, яке
визнає центр сертифікації. Чи приймається марка, зареєстрована в Україні, — *уточніть у
конкретного центру сертифікації*. Вартість — зазвичай сотні або понад тисячу доларів на рік.

**CMC (Common Mark Certificate)** — дешевша альтернатива без торговельної марки: потрібно
довести, що логотип **публічно використовується щонайменше 12 місяців** (наприклад, архівні
копії сайту у Wayback Machine). Gmail приймає CMC (без синьої позначки); інші сервіси — *за
власною політикою, перевіряйте*.

## 6. Перевірка

- **BIMI Inspector / генератор записів** від BIMI Group:
  [bimigroup.org](https://bimigroup.org/) — перевіряє DNS-запис, доступність і формат SVG,
  сертифікат.
- Запис у DNS: `dig +short TXT default._bimi.example.com`
- DMARC: `dig +short TXT _dmarc.example.com` — має містити `p=quarantine` або `p=reject`.
- Сторонні сервіси на кшталт MXToolbox (BIMI Lookup) також перевіряють запис.

Поштові сервіси кешують BIMI: після змін логотип може з'явитися (або оновитися) лише через
кілька годин чи днів.

## 7. Часті проблеми

- **Логотип не з'являється в Gmail** — немає VMC/CMC або DMARC має `p=none`/`pct<100`.
- **Валідатор каже «invalid SVG»** — залишились атрибути `x`/`y` на `<svg>`, немає `<title>`,
  є `<image>` або скрипти, неправильний `baseProfile`.
- **Валідатор не може завантажити логотип** — URL віддає HTML (див. блок nginx у розділі 3),
  переспрямовує або має недійсний сертифікат.
- **Листи з піддомену без логотипа** — BIMI шукається для домену з `From:`; для піддомену
  потрібен свій запис `default._bimi.sub.example.com` (або сервіс бере запис організаційного
  домену — поведінка відрізняється між сервісами).
